- PostGIS: `generate`, `push` and `pull` handle every `geometry` and `geography` typmod, GeoJSON defaults and arrays; casing, SRID `0` and the implicit `geography` SRID no longer produce diffs (fixes `geometry(Point)` vs `geometry(point)` push noise); `pull` renders `geometry({ type: 'MultiPolygon', srid: 4326 })` and GeoJSON literal defaults
- Views: a changed definition is applied with `CREATE OR REPLACE VIEW` when the new columns keep the old ones as a prefix, which PostgreSQL requires; otherwise the view and every view that selects from it are dropped in dependency order and created again, and granted again. The view entity records its columns and its comment (`pgView(...).comment('...')`), written with `COMMENT ON VIEW`; `pull` reads the comment back. See `docs/views-comments-grants.md`
- Privileges: `pgGrant()` declarations are granted and revoked by `generate` and `push`, on tables, views and schemas; `push` manages the privileges of the roles the schema names or the roles filter accepts and leaves every other role's alone; `pull` renders `pgGrant()`
- **Breaking:** the postgres snapshot is version 9; run `drizzle-kit up`
- Functions, triggers and extensions: `pgFunction()`, `pgTrigger()` and `pgExtension()` declarations are schema entities. `generate` creates a function after the tables its body reads and before the indexes, the views and the triggers that call it, replaces it in place when its body, its attributes or its comment change, and drops and creates it when its signature changes, with the triggers, the indexes and the views that call it dropped before and created after; a trigger is replaced in place; an extension is created first and dropped last, and its version is updated in place (`ALTER EXTENSION ... UPDATE TO`) when the declared one differs. `pull` reads the functions of the schemas (not the ones an extension installed), the user triggers of the tables and every extension but `plpgsql`, and renders them as `pgFunction()`, `schema.function()`, `pgTrigger()` and `pgExtension()`; `push` diffs them against the database. A declared type is compared as Postgres prints it (`int` and `integer` are one), the attributes in one spelling and order, a trigger's events in one order, so a declaration and its introspection compare equal. An extension declared without a version accepts the installed one, and `push` never drops an extension the schema does not declare
- The cluster's own roles (`pg_*`, the bootstrap superuser) and the role the session logged in as are never the schema's: `entities.roles: true` used to plan `DROP ROLE` for every one of them on `push`, statements Postgres refuses. PostgreSQL only
- An index's `WITH` options are compared as Postgres stores them: a declaration that quotes a value (`search_tokenizer='unicode_words(ascii_folding=true)'`, which `CREATE INDEX` needs) and the unquoted `reloptions` value are one option, so `push` no longer recreates such an index on every run. PostgreSQL only
- `transform`: a config may name transforms of the loaded schema files, `(exports, path) => more exports`, applied in order to each file before the schema objects are collected; what a transform returns joins the file's exports after them, in the order returned (a replaced export moves to the transform's place), so a schema can be derived at load time from what a file holds and created in the order the transform gives. `generateDrizzleJsonFromFiles(paths, { transforms, prevId, filters })` is the API's counterpart. PostgreSQL only
